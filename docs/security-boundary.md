# Security Boundary

## Current guarantee

Blackwall Core produces deterministic `allow` or `deny` decisions for validated policy inputs. It bounds session count, request count, frame size, and audit capacity. It rejects unknown fields, expired grants, revoked grants, identity mismatch, malformed resources, replay, and backwards wall-clock movement.

## Current non-guarantees

This repository does not:

- sandbox or launch arbitrary agents;
- block direct operating-system access;
- enforce filesystem or network policy;
- protect the policy engine from the current user or an administrator;
- authenticate a process merely because it can access a stream;
- provide tamper-resistant or persistent audit storage;
- detect whether a request was generated by AI;
- classify software as safe or malicious;
- provide real-time antivirus protection.

`enforcementLevel: "L0"` is mandatory in current decisions so downstream software cannot mistake policy simulation for OS enforcement.

## Trust assumptions

The owner that creates sessions is trusted. It must authenticate the workload, protect bearer capabilities, provide policy and time, control revocation, and expose only a submit-only interface to the agent. A bearer capability must never appear in a URL, command line, log, prompt, or audit event.

## Production requirement

A future `L2` claim requires evidence that the workload cannot directly read an unapproved user file, start an unrestricted child, or obtain ambient network access. A future `L3` claim requires a protected service and system controls with tested crash, restart, upgrade, rollback, and uninstall behavior.
